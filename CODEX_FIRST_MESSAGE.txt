지금부터 EmoLabel 2.0이라는 완전히 새로운 로컬 연구용 프로그램을 개발하고 싶다. 지금 이 폴더에 이전 ChatGPT 대화의 핵심 내용과 개발 규칙을 정리해 두었다.

먼저 `AGENTS.md`, `README_START_HERE.md`, `PROJECT_CONTEXT.md`, `REQUIREMENTS.md`, `ARCHITECTURE.md`, `ROADMAP.md`, `EVALUATION_PLAN.md`, `OSS_REVIEW.md`, `DECISIONS.md`를 모두 읽어라.

중요한 규칙:
- **이 폴더만** 다룬다. 이전 EmoLabel 원본 및 예전 Companion, GitHub 저장소는 건드리거나 읽거나 복사하지 마라.
- GitHub/git/remote/clone/push를 사용하지 마라. 지금은 완전한 새 로컬 프로젝트다.
- Hugging Face Hub/인증/모델 다운로드를 사용하지 마라.
- 새 프로그램은 권한이 확보된 한국어 영상에서 감정 라벨링용 3~12초 클립을 뽑고, 로컬 AI가 한국어 대사를 감정 사전 분류하고, 사람이 최종 검수한 데이터만 저장하며, 처리시간·정확도·작업시간을 분석해야 한다.
- AI 예측은 gold label이 아니다. 승인 상태는 annotation.json 존재와 별도로 기록한다.
- API 키나 개인 연구 데이터를 외부에 보내지 마라. 데이터 수집 권한과 모델 배포 라이선스를 검토하라.
- 나는 개발 과정을 제대로 이해하고 발표해야 하므로, 모든 기술과 코드를 초보자가 이해할 수 있도록 설명해라.

**첫 번째 요청은 읽기 전용 분석이야. 코드를 수정하거나 패키지를 설치하지 마.**
1. 제공된 문서와 기본 코드의 상태를 확인하고, 이미 구현된 것과 앞으로 해야 할 것, 단순 제안/검증 안 된 사실을 명확히 구분해라.
2. 제안한 파이프라인을 기술적으로 검토하고 더 현실적인 개선점과 위험을 설명해라.
3. Phase 0과 Phase 1에서 정확히 어떤 파일, 함수, 데이터 구조, 테스트케이스부터 만들지 제안해라.
4. 원본·이전 프로젝트 격리, Hugging Face 미사용, 로컬 개인정보 보호를 어떻게 보장할지 확인해라.
5. 검수 시간·런타임·채택률·한국어 감정 평가 계획까지 포함해서 한국어로 보고해라.

내가 계획을 확인한 후 구현을 승인할 것이다.
